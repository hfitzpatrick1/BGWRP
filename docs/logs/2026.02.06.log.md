# 2026.02.06 - Config Shadowing, Logging, Persistent Variable Fixes

## Summary

Fixed a chain of failures preventing multi-dataset analysis from completing. Three categories: config resolution, case-sensitive lookups, and unguarded persistent variables in MATLAB.

---

## Problem 1: `config.dataset_smoothing` Not Loading

### Symptom
`config.dataset_smoothing DOES NOT EXIST` in log output. All datasets fell back to default smoothing.

### Root Cause
Two `config.m` files existed: the intended one at project root (with `dataset_smoothing`) and a stale copy at `src/config.m` (without it). `BGWRP_Toolkit.m` line 17 runs `addpath(genpath(script_dir))` where `script_dir` = `src/`, so MATLAB resolved `config()` to the stale `src/config.m`.

### Fix
Merged unique values from `src/config.m` into root `config.m`, then deleted `src/config.m`.

### Rule
One `config.m` at project root. Never place any file under `src/` that shares a name with a root-level file -- `addpath(genpath('src'))` will shadow it.

## Problem 2: `dataset_smoothing` Lookup Case Mismatch

### Symptom
`No config found for test_label="PT01a_Recovery_short"` despite `config.dataset_smoothing.PT01A_RECOVERY_SHORT` existing.

### Root Cause
MATLAB struct field access is case-sensitive. Config keys are UPPERCASE; test labels from directory names are mixed case.

### Fix
`analyze_das_data.m` line 254:
```matlab
test_label_upper = upper(strrep(test_label, ' ', '_'));
if isfield(config.dataset_smoothing, test_label_upper)
```

### Rule
`config.dataset_smoothing` keys are UPPERCASE (`PT01A_RECOVERY_SHORT`). Directory names in `_active/` are mixed case (`PT01a_Recovery_short`). Always normalize with `upper(strrep(name, ' ', '_'))` before lookup.

## Problem 3: `chart_logger` Crashes on Uninitialized Persistent Variables

### Symptom
`Operands to the logical AND (&&) and OR (||) operators must be convertible to logical scalar values` at `chart_logger.m` lines 65 and 96. Killed the analysis loop after the first dataset's plots, preventing subsequent datasets from plotting.

### Root Cause
The separate chart log file was disabled (`chart_logger('init', config)` commented out in `init_chart_logging.m`), so `chart_logger`'s persistent variables (`session_active`, `log_file_handle`) stayed as `[]`. MATLAB treats `[] && ...` as an error.

### Fix
Added `~isempty()` guards at both locations:
```matlab
if ~isempty(session_active) && session_active && ~isempty(log_file_handle) && log_file_handle ~= -1
```

### Rule
MATLAB `persistent` variables default to `[]`. Always guard with `~isempty(var)` before any logical operation. `[] && true` is a runtime error in MATLAB, not falsy.

## Logging: How and Why

### Problem
The Cursor IDE MATLAB extension does not reliably expose `fprintf` console output. An LLM cannot read the MATLAB command window. All `fprintf` output is effectively invisible.

### Solution
`console_log` (`src/_utils/console_log.m`) wraps `fprintf` to write simultaneously to the MATLAB console and a persistent text file. This file is the canonical pipeline output.

**API:**
```matlab
console_log('init', filepath)       % Open log file (overwrites previous)
console_log('format %s\n', args)    % Write to console + file (same syntax as fprintf)
console_log('close')                % Flush and close
```

**Initialization** happens in the run script before calling `BGWRP_Toolkit`:
```matlab
log_path = fullfile('C:', 'Coding', 'BGWRP', 'data', '_BATCH', '_log', 'console_log.txt');
console_log('init', log_path);
```

**Output location:** `data\_BATCH\_log\console_log.txt` (overwritten each run, not timestamped).

**`chart_logger`** is a secondary system (`src/_utils/chart_logger.m`) that previously wrote chart-specific messages to a separate timestamped file. It is now disabled; all its output routes through `console_log` instead. To re-enable: uncomment `chart_logger('init', config)` in `src/_utils/init_chart_logging.m`.

**`console_log` is not `fprintf`.** It does not accept a file handle as its first argument. Code that needs to write to its own file handle must use `fprintf(fid, ...)` directly.

### For any LLM working on this codebase
After running a MATLAB script, read `data\_BATCH\_log\console_log.txt` for the pipeline output. Do not attempt to read the MATLAB console -- it is not accessible.
