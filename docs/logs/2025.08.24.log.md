# 2025.08.24 - BGWRP Pipeline Improvements

## Primary Issue: Vertical Striping Artifacts
DAS waterfall plots showed vertical striping artifacts with 66.5% RMS amplitude variation at 60-sample intervals.

## Root Cause Analysis

### TDMS Metadata Investigation
**File**: `src/diagnostic/diagnose_tdms_metadata.m`
- **Created**: Unified discovery utility, metadata extraction for 91 TDMS fields
- **Finding**: All scaling parameters (UnitCalibration_nm, ReceiverGain, SamplingFrequency_Hz) constant across files
- **Conclusion**: Hardcoded scaling (adc_scalar = 1/8192, data = 116*data) in `Silixa_TDMSDataToPhysicalDispRate.m` was correct

### Order of Operations Problem (CRITICAL)
**File**: `src/prepare/concatenate_and_downsample.m`
- **Original**: Decimate each file individually, then concatenate
- **Problem**: MATLAB's `decimate()` applies different Chebyshev IIR anti-aliasing filters per file
- **Result**: Filter boundary effects create vertical discontinuities at file transitions

## Primary Solution: Pipeline Order Fix

### Core Fix - Concatenate First, Decimate Second
**Files**: Replaced `concatenate_and_downsample.m` with decomposed functions
- **New approach**: Load all raw 100Hz data → concatenate → decimate entire unified dataset
- **Critical insight**: Treat file boundaries as arbitrary breaks in continuous signal
- **Result**: Single consistent anti-aliasing filter applied across entire time series

### Code Architecture Changes
```matlab
// OLD (caused striping)
for each file:
    data = load_file()
    decimated = decimate(data, factor)  // Individual filter per file
    concat_data = [concat_data; decimated]

// NEW (fixed striping)  
for each file:
    raw_data = [raw_data; load_file()]  // Concatenate raw first
// Then unified decimation:
decimated = decimate(raw_data, factor)  // Single filter for entire dataset
```

**Files Created**:
- `src/prepare/concatenate_mat.m` - Pure concatenation logic
- `src/prepare/downsample_mat.m` - Pure decimation with validation  
- `src/prepare/process_mat_data.m` - Integrated orchestrator

### Discovery System Refactor
**File**: `src/_utils/discover_datasets.m`
- **Created**: Unified dataset discovery for all modes
- **Problem**: Diagnostic modes used hardcoded paths while prep modes used dynamic discovery

**File**: `src/BGWRP_Toolkit.m`
- **Updated**: Lines 812-843, diagnostic modes now use `discover_datasets('raw')`
- **Fixed**: Inconsistent directory discovery between prep and diagnostic modes

## Head Data Pipeline Integration

### Filename Dependency Elimination
**Problem**: Pipeline relied on hardcoded filename patterns (`head_a_z*.mat`) causing data overwriting bugs
**Files**: `src/analyze/analyze_head_data.m`, `src/plot/generate_plots.m`
- **Root cause**: Generic `z\d+` extraction caused later files to overwrite earlier data
- **Solution**: Complete architectural refactor to metadata-driven processing

### New Directory Structure
**Input Format**: Hierarchical `_das`/`_head` subdirectories
```
dataset_name/
├── _das/     # TDMS files
└── _head/    # Individual zone MAT files (head_*.mat)
```
**Files**: `src/_utils/organize_workspace.m`, `src/BGWRP_Toolkit.m`
- **Updated**: Input detection to scan subdirectories vs flat structure
- **Preserved**: `_das`/`_head` structure through intermediate processing
- **Output**: `_active/dataset/_das/` and `_active/dataset/_head/`

### Head Data Preprocessing Stage
**File**: `src/prepare/process_head_data.m` (new)
- **Function**: Combines individual zone files into unified `head_data.mat`
- **Validation**: Timestamp consistency across zones
- **Structure**: `head_data.zones.z1.{Date,Drawdownft,Depthft}`
- **Integration**: Added as Step 2A in `BGWRP_Toolkit.m` between TDMS conversion and concatenation

### Analysis Logic Overhaul
**File**: `src/analyze/analyze_head_data.m` (complete rewrite)
- **Old**: Loaded all head files for each test (data overwriting bug)
- **New**: Loads single combined `head_data.mat` per dataset
- **Fixed**: Data loss where PT01a zones showed 48 points in calculation but 0 in plotting
- **Storage**: Direct field placement (`avg_recovery_rate` vs `stats.avg`)

### Configurable Zone Display
**Files**: `src/config.m`, `src/plot/generate_plots.m`, `src/plot/*.m` (4 new helper functions)
- **Configuration**: Per-dataset zone selection (`'all'`, `'z3'`, `{'z2','z3'}`)
- **Display modes**: `'multiple'` (colored lines + legend), `'single'`, `'average'`
- **Default**: Show all available zones with different colors
- **Eliminated**: Arbitrary "first zone with valid data" selection logic

### Timing Configuration Restructure
**Files**: `src/BGWRP_Toolkit.m`
- **Storage**: Timing configs moved to `_active/dataset/_das_timing/`
- **Loading**: Updated to use subdirectory structure
- **Integration**: Maintains dataset-specific timing isolation

### Dynamic Bounds Fix
**Problem**: Logical indexing error when applying spatial masks to 1D time series
**File**: `src/plot/get_plot_bounds.m`
- **Fix**: Remove `zone_mask` application to `analysis_strain_rate` (already 1D)
- **Result**: Dynamic bounds calculation works for displacement/strain plots

## Technical Notes
- Memory usage: 100x increase during concatenation (35,994 vs 360 samples)
- Compute time: Linear scaling with dataset size
- Trade-off acceptable for artifact elimination
- All modes (prep, analyze, diagnostic) verified functional after changes
- Head data integration maintains co-location with DAS data in `_active`
- Pipeline now completely filename-agnostic, metadata-driven processing
